# Incident #005 — High CPU Usage Investigation

## Environment
- Ubuntu 26.04 (WSL2)
- Apache Tomcat 11
- Linux process monitoring tools

## Incident Summary
A controlled high-CPU workload was generated in a local Linux environment to simulate a performance incident.

## Baseline
Initial system checks showed:
- Total RAM: 7.5 GiB
- Available RAM: 6.4 GiB
- Swap usage: 0 B
- Tomcat CPU usage: approximately 1.4%

## Simulation
A CPU-intensive workload was started using:

`timeout 60s yes > /dev/null &`

The process was configured to terminate automatically after 60 seconds.

## Investigation
The following command identified the processes consuming the most CPU:

`ps aux --sort=-%cpu | head -n 5`

Results:
- Process: yes
- PID: 2304
- CPU usage: 99.9%
- Memory usage: approximately 0%
- Process state: R (Running)

A subsequent simulation also showed PID 2422 using 99.8% CPU.

## Root Cause
The high CPU usage was intentionally generated by the `yes` command.

## Resolution
The simulated workload ended, and the CPU-intensive process was no longer present in the process list.

## Validation
After the workload ended, the process list showed Apache Tomcat using approximately 1.2% CPU, with no `yes` process among the top CPU consumers.

## Lessons Learned
- Establish a baseline before investigating performance problems.
- Use `ps` to identify CPU-intensive processes.
- Distinguish single-core CPU utilization from total CPU utilization.
- Examine process IDs and states.
- Verify that resource usage returns to normal after recovery.

## Scope
This incident was simulated in a local training environment, not in production.
